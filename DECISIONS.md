# DECISIONS.md

One line per decision, chronological: `<decision> — <reason>`.

## Phase 0 — Scaffold

- Repo root is the working directory itself (not a nested `visual-campus/` folder) — the spec tree only names the root; the project directory was opened as the repo.
- The spec was supplied as `SPEC.pdf`; `SPEC.md` was generated from its text layer with `pdftotext -enc UTF-8` and section headers restored — Section 4 requires `SPEC.md` in the repo root; `SPEC.pdf` is kept as the original.
- Several long lines are clipped inside the PDF itself (Commons `iiextmetadatafilter` list after `Obj`, Flickr `extras` after `descrip`, the Commons exclusion regex after `\.t`, `VISION_SYSTEM` after "You receive N", two `//` comments in the vision header, the description prompt, the spelling prompt) — each reconstruction is recorded in the phase that implements it.
- Local development uses a Python 3.12 venv (`.venv`, git-ignored) because Python 3.11 is not installed on the build machine; the Docker image stays `python:3.11-slim` as fixed by Section 16.1 — every pin was resolved for `--python-version 3.11` on manylinux with `pip download` to confirm cp311 wheels exist.
- `numpy==2.4.6` is pinned (not the newest 2.5.x) — numpy 2.5 ships no Python 3.11 wheels, which would break the Docker build.
- Runtime pins live in `backend/requirements.txt`; dev/test pins (`pytest`, `pytest-asyncio`, `respx`, `ruff`) in `backend/requirements-dev.txt` which includes the runtime file — keeps the Docker image free of test tooling while every version stays pinned with `==`.
- Docker is not installed on the build machine, so the `docker build` / `docker run` gate is substituted by an equivalent local check: pip resolution for py3.11/linux, `npm ci && npm run build`, uvicorn started from `backend/` with the built SPA copied to `app/static`, `curl /api/health` — the Dockerfile is Section 16.1 verbatim, so the steps are the same ones the image runs.
- Added `.dockerignore` (node_modules, dist, .venv, data, .git) — the spec Dockerfile does `COPY frontend/ ./` and `COPY backend/ ./`, which would otherwise copy local build artefacts into the image.
- `react-router-dom` 6.x is used for the two routes `/` and `/u/:qid` — it is a router, not a component library, and the spec's `:qid` notation is react-router syntax.
- Frontend pinned to Vite 7.3.6 / TypeScript 5.9.3 / `@vitejs/plugin-react` 5.2.0 rather than the newest Vite 8 / TypeScript 7 majors — stability during the hackathon; Vite 7 needs Node ≥ 20.19, which `node:20-alpine` provides.
- `react-leaflet` pinned to 4.2.1 — 5.x requires React 19 while the spec fixes React 18.
- Tailwind CSS 4.x via the `@tailwindcss/vite` plugin — no PostCSS config needed; one `@import "tailwindcss"` in the stylesheet.
- `Settings` reads `.env` from both the repo root (`../.env` relative to `backend/`) and `backend/.env`, environment variables always win — `docker compose` passes the root `.env`, while `uvicorn` is started from `backend/` locally.
- Empty-string environment values (`TEXT_MODEL=`, `GEMINI_API_KEY=`) are treated as unset — `.env.example` ships every variable, and an empty key must not be sent to the SDK.
- `/api/health` `version` is `GIT_SHA` env if set, else `git rev-parse --short HEAD` at startup, else `dev` — the spec Dockerfile has no build-arg, and there is no `.git` inside the image.
- Retry policy treats `httpx.NetworkError`, `httpx.ConnectTimeout` and `httpx.RemoteProtocolError` as "connection errors"; read timeouts are not retried — a retried read timeout would silently double a stage's time inside the 27 s budget.
- SPA fallback is a catch-all route registered after `/api`; unknown `/api/*` paths return the JSON error envelope, never `index.html` — Section 12 error format must hold for every API path.
- `Warning` model keeps the spec's name although it shadows the Python builtin — the frontend `types.ts` mirrors names exactly.
- `ruff` 0.16.8 is pinned and its *default* rule set (which is broad in 0.16: UP, BLE, RUF, ASYNC, …) is used unchanged; a root `ruff.toml` mirrors `backend/pyproject.toml` so `scripts/` is linted too — Section 3 says "ruff with default rules".
- `.gitattributes` forces LF in the repository — the Windows build machine has `core.autocrlf=true`, and the Docker image is Linux.

## Phase 1 — Resolver

- QID label check (Section 7.1): all 9 `UNIVERSITY_QIDS` and all 7 `CITY_QIDS` labels were verified live with one `wbgetentities&props=labels&languages=en` call each (`scripts/probe_wikidata.py`); none removed — Q7930989 is labelled "city or town" and Q1093829 "city in the United States", synonyms of the spec wording.
- `Q2385804` (educational institution) is essential — Kostanay Regional University (Q123694980) passes the university filter only through it (its description "education organization in Kostanay" matches neither regex).
- Filter (b) is applied to the description with the query text and the entity's own labels removed first (whole-word, case-insensitive) — the literal rule keeps sub-units whose description merely names the parent ("research archive for Nazarbayev University", "school at the Massachusetts Institute of Technology"), which made the gate "Nazarbayev University → 1 candidate" unreachable; rule (a) is unchanged.
- Filter (b) is never applied to humans (P31 contains Q5) — a biography "Ph.D. Lomonosov Moscow State University, 1984" appeared as a candidate for "МГУ"; rule (a) can never match a human anyway.
- One extra `wbsearchentities` call (en) for `"<q> university"` is issued when the query itself contains no university-like word; its hits rank after every direct hit — with the three spec searches "Columbia" yields exactly one university (Q49088) among cities, a record label, CBS and a plant genus, so the gate "Columbia → several with descriptions" needs it. Not fired for an empty query.
- Fallback 1 (Wikipedia opensearch → pageprops) sets `corrected_query` to the top candidate's label when it differs from the query (`suggestions_used` stays `False`) — the spec only sets it in the LLM step, but the gate "Massachusets Institut of Technology → MIT via fallback with corrected_query" must hold without an AI key, and the UI copy "Показаны результаты по исправленному названию" is exactly right for it.
- Added a fallback between opensearch and the LLM step: Wikidata full-text search `action=query&list=search&srsearch={q}&srnamespace=0&srlimit=10&format=json` → `query.search[*].title` (QIDs) → the usual entity fetch, filter and ranking — `wbsearchentities` is a label/alias *prefix* matcher and cannot find the Section 13 example chip "Kostanay Regional University" (label "Akhmet Baitursynuly Kostanay Regional University", no Wikipedia article); without the fallback that chip showed the not-found state whenever no AI key is present.
- The pageprops call adds `redirects=1` (a documented MediaWiki parameter) and maps `query.redirects[]` — opensearch returns redirect titles and without it the redirect page has no `wikibase_item`, silently losing QIDs (probed: "L.N. Gumilyov Eurasian National University", ruwiki "Massachusetts Institute of Technology").
- Real-response shapes (probed, recorded because Section 7.1 does not describe them): opensearch returns a 4-element JSON array (titles at `[1]`); `query.pages` is keyed by pageid in arbitrary order and pages without an item have no `pageprops` key; `wbsearchentities` hits may lack `description`; entities may have no en label (`mul`-only labels) → `Candidate.label` falls back to the search-hit label; REST summary `extract` may start with whitespace and contain NBSP/combining marks → NFC-normalised and stripped.
- Claims with `rank == "deprecated"` are skipped in addition to non-`value` snaks — real entities carry deprecated P856 websites (Columbia SC, Columbia MO) and identifiers.
- Membership checks on P31 (university rule (a), city chain "intersects CITY_QIDS") consider every non-deprecated claim regardless of rank; single-valued props (P131[0], P17, P159, P625, P856, P373, P18, P154) keep "preferred, else first" — Zurich's "big city" claim is normal-rank next to preferred municipality classes, and the literal preferred-only reading made ETH Zurich show its own main building as the city at 0.0 km.
- The P159 (headquarters) city fallback is refused when that entity's P31 contains a building class (Q41176 building, Q811979 built structure, Q209465 campus, Q1497375 architectural ensemble; labels verified live), falling through to "first hop with P625 and a sitelink" — otherwise the university's own building became the "city". The P159 entity is fetched in the same `wbgetentities` call as the first P131 hop.
- City chain guards against P131 cycles (visited set) and stops when a hop cannot be fetched; the country label (P17) is fetched in parallel with the chain via `props=labels` — a country entity's full claims are megabytes.
- Country (P17) tie-break, deviation from "else first": when no claim is preferred, claims with an end-time qualifier (P582) are skipped and the id that the resolved city also lists as its country wins — Soviet-era universities list "Soviet Union" before "Kazakhstan" with equal rank (Astana Medical University Q4287774). Candidate rows (no city entity fetched) still use the first remaining P17.
- Alias dedupe is case-insensitive preserving first occurrence; P1448/P1813 use all non-deprecated ranks so "Boston Tech" survives next to the preferred "MIT"; the name itself is not removed from aliases — the spec says dedupe only.
- `Candidate.city` is the label of P131[0] (e.g. Manhattan for Columbia); `Candidate.description` is the entity description en → ru → search-hit description.
- `wikipedia_url` is built from the sitelink title with spaces → `_` and no percent-encoding, as the spec states; the REST summary page URL comes from `content_urls.desktop.page`.
- Timeouts: Wikidata 5 s (spec), REST summary 4 s (spec), opensearch/pageprops 5 s (spec silent; Wikidata's value reused).
- `/api/search` has an overall deadline `SEARCH_DEADLINE_S = 12` (`asyncio.wait_for`) after which it answers `candidates=[]`, uncached — Section 6 gives Stage A 5 s, but the search fallback chain includes the 6 s LLM step, and without a deadline an unreachable Wikidata held the request ~33 s in retries. The profile pipeline applies the 5 s Stage A limit to `resolve_university` separately.
- The ≤ 3 LLM-suggested names are searched in parallel (`gather`, `return_exceptions=True`); the first name in the model's order that yields candidates becomes `corrected_query`.
- The `q` length rule (2–120) is enforced on the whitespace-collapsed query, both in the route and inside `search_universities` — a whitespace-only query otherwise passed FastAPI validation and returned unrelated universities.
- `resolve_university` raises `ResolverUnavailableError` when Wikidata itself is unreachable and returns `None` only for missing / non-university entities — Section 12 distinguishes 503 from 404; `get_entities` keeps degrading to `{}` everywhere else.
- Only non-empty search results are cached (6 h by normalised query); a cache hit returns the stored response with `query` replaced by the current text — a transient outage must not poison the cache.
- 422 envelope message is built from the individual validation errors ("q: String should have at least 2 characters") — the spec requires human text, not a Python repr.
- The AI client creates the SDK with its own retries disabled and uses tenacity as the only retry layer (2 retries, 1 s → 4 s backoff on 429 / 5xx / connection / timeout errors) — stacking the SDK's own retries would allow 9 attempts and blow the 30 s budget.
- AI per-call timeout defaults to 30 s (the SDK default is far longer); startup check 10 s with prompt "Reply with the single word OK." (spec: "one tiny text call, max_tokens=5"); spelling 6 s.
- Spelling prompt reconstruction (clipped in the PDF after "official English names of"): `…of the university they meant, as used on Wikipedia and Wikidata. No explanations, no markdown, no text outside the array.` — constant in `backend/app/ai/prompts.py`.
- Cache stores JSON with `ensure_ascii=False, default=str`; rows with unparseable `created_at` or invalid JSON are ignored as misses; expired rows are overwritten on the next write; every cache failure (including an unopenable path) is a warning and a miss, never an error — a cache failure must never break a request.
- An unwritable `CACHE_DIR` no longer prevents startup (`mkdir` failure is a warning) — the app must keep serving with thumbnails unavailable.
- Fixtures are unmodified real API responses saved by `scripts/probe_wikidata.py`, `scripts/probe_wikipedia.py` and `scripts/probe_resolver_review.py` (a few were saved by ad-hoc calls with the same parameters during implementation; content spot-checked byte-for-byte against the live API by the review) — the large ones (Columbia entities 2.3 MB, Zurich hops 1.4 MB) are kept whole because trimming would make them non-real.
- Gate status: all five search gate queries and the MIT header were verified live (no key needed); the LLM spelling step (7.8 b) is covered by mocked tests only at Phase 1 time.

## Phase 2 — Sources + processing (and the customer's key amendment)

- Amendment A (customer, 2026-09-18, appended to SPEC.md): the only key is `GEMINI_API_KEY`; no Anthropic package or variable; Flickr optional and silent; Google CSE optional and silent; every gate must pass with `.env` = `GEMINI_API_KEY` + `CONTACT_EMAIL` — applied from Phase 2 on; the Phase 1 Anthropic client was replaced, not kept as a second provider.
- Gemini is called through the official `google-genai==2.24.0` SDK (`genai.Client(api_key=...)`, `client.aio.models.generate_content`); `anthropic` was removed from `requirements.txt` — Amendment A forbids a second provider implementation.
- Default `VISION_MODEL=gemini-3.5-flash-lite` (`TEXT_MODEL` = same) — the live models list for the customer's key contains it, Google's docs recommend the flash-lite tier for classification, and `scripts/probe_gemini.py` measured ~0.8 s per call and no 429 across 12 concurrent calls on the free tier.
- Thinking is minimised on every call (`thinking_level=MINIMAL` for Gemini 3.x, `thinking_budget=0` for 2.5 models); a model that rejects the thinking config with a 400 is retried once without it and remembered — classification and 3–5-sentence descriptions need speed inside the 30 s budget, not deliberation.
- JSON answers are requested with `response_mime_type="application/json"` in addition to the prompt instruction; the Section 9 fence-stripping / recovery parser is kept as a fallback — belt and braces for the "≥ 90 % of batches parse on the first attempt" gate.
- The customer's real `GEMINI_API_KEY` was moved from the committed `.env.example` into the git-ignored `.env`; `.env.example` ships an empty value — Section 2 rule 5 (secrets only from the environment, never committed).
- Wikimedia's image CDN (`upload.wikimedia.org`) enforces the robot policy against a User-Agent whose contact is `team@example.com` (HTTP 403 "Please honor our robot policy"), while `thumb.wikimedia.org` (where Commons serves scaled thumbnails) accepts it — `CONTACT_EMAIL` must be a real address in production (documented in `.env.example`/README); files that Commons returns unscaled (≤ 640 px wide) fall back to a 500 px thumbnail on `thumb.wikimedia.org` when the original answers 403 (500 px is the width the thumbnailer accepted in probing; 480/512/640 returned 400).
- The 8-slot download semaphore covers every `*.wikimedia.org` media host (`upload.wikimedia.org` and `thumb.wikimedia.org`) — real Commons `thumburl`s now point at `thumb.wikimedia.org`.
- Section 7.4A (Commons geosearch, replacing Flickr as the default geo source): `generator=geosearch&ggscoord={lat}|{lon}&ggsradius=1000&ggsnamespace=6&ggslimit=50&ggsprimary=all&prop=imageinfo|coordinates` + the 7.3 prop block; new `SourceType.commons_geo` (base 0.40, reason `commons_geo_source`) placed between `commons_category` and `flickr_geo` in `SOURCE_PRIORITY` — same distance-to-campus signal as Flickr, no key.
- The Flickr source (Section 7.4) is kept for deployments that set `FLICKR_API_KEY`; without the key the registry simply omits it (debug log only, no warning) — Amendment A.
- Stage C URL-dedupe keeps the higher-priority source's candidate but borrows `geo`/`distance_m` and the subcategory hint from a lower-priority duplicate — a category photo that geosearch also returns must still earn the geo bonus.
- Underscore is treated as a separator in the Section 10 normalisation (`[^\w\s]|_` → space) — Python's `\w` includes `_`, and Commons/official-site filenames use `_` for spaces, so the literal regex never matched names inside filenames.
- Logo matches (Section 8, sha1 or pHash ≤ 8 to the P154 logo) are counted in `stats.irrelevant_removed`, not in `duplicates_removed` — they are not duplicates of another candidate.
- Selection caps (Section 11: 12 per category, 6 city, 45 total, 15 hidden) are applied as *running* caps while photo chunks are streamed (batches arrive best-source first) and the blocking `Profile` re-sorts the same set with `finalize_selection` — a stream cannot retract photos, so the streamed set and the blocking set must be identical.
- Commons `image_url` is the 640 px `thumburl` (spec 7.3: "thumburl → image_url to download"); `Photo.image_url` therefore opens the 640 px rendering while `source_page_url` opens the Commons file page with the original.
- The P18 main image bypasses the size and filename filters (only the mime filter applies) — it is the entity's declared main image, and Section 10 gives it the highest base weight.
- Commons `DateTimeOriginal` is HTML-stripped first and only the `^(\d{4})[-:/](\d{2})[-:/](\d{2})` prefix produces a `taken` date; values like "1969", "circa 1890-1900", "August–November 1921" or "11 March 2018 (according to Exif data)" fall back to the upload timestamp labelled `uploaded` — Section 2 rule 2 (never guess a date).
- No real Flickr response exists (no key): `tests/fixtures/flickr_photos_search_sample.json` is a clearly labelled synthetic sample of the documented response shape (top-level `_note`), to be replaced by `scripts/probe_flickr.py` output when a key is available.
- `scripts/eval.py --no-vision` runs the app in-process (httpx ASGI transport inside the lifespan) with `GEMINI_API_KEY` cleared — no server or key is needed for the Phase 2 gate; `refresh=1` is the default (Section 15.2) and every `thumb_url` is fetched so "a thumb that loads" is verified.
- Section 7.4A request adds `colimit=50` (documented MediaWiki parameter) — without it the `coordinates` prop returns coordinates for only 10 of the 50 geosearch pages (probed), losing the distance signal for 80 % of the files.
- Geosearch coordinates: the entry with `primary == ""` (the JSON rendering of true) is preferred, non-`earth` globes are ignored, `distance_m` is rounded to 1 decimal.
- `choose_subcategories`: with fewer than 3 regex matches the matching titles come first and the list is filled to 8 in API order — the literal "first 8 in API order" would drop a matching "Campus of X" that sorts late; identical to the spec for 0 matches and for ≥ 3 matches.
- Commons `query.pages` is a pageid-keyed object whose order is not the generator order; search results are re-sorted by the `index` field so "API order" means the search rank.
- The Commons category source runs the category listing and the subcategory listing in parallel, then the chosen subcategories in parallel; subcategory listings never follow continuation (spec: "no continuation").
- A source that failed only partially (one subcategory, one search leg, the continuation page) keeps the photos it found, records the error, and does NOT emit `source_unavailable` — the UI copy "источник недоступен, профиль построен без него" would be false; the warning is emitted only when a source contributed nothing.
- A 200 response carrying a MediaWiki `error` object (or a Flickr `stat: "fail"`) counts as a failed request.
- Commons `title` is ImageDescription → else ObjectName (HTML stripped, ≤ 300 chars); `description` stays `None` so the same text is not matched twice.
- Flickr `datetakenunknown == "1"` → the date is kept but labelled `uploaded` (Flickr documents that `datetaken` then holds the upload date); `min_taken_date` is sent as `2008-01-01`.
- Multi-word names tolerate an inflected last word in `name_in_metadata` (leading words whole, last word may be a prefix of the text token; single-word names must match whole) — Russian/Kazakh case endings ("Назарбаев Университета", "Университеті") must still count, while "tech" must never match "technology".
- Palette images with transparency are converted through RGBA before RGB — Pillow's warning path otherwise; the result is the same RGB thumbnail.
- Download-stage numbers on the Phase 2 gate (no vision): MIT 120 candidates, 87 downloaded within the 8 s stage budget, 32 timed out (the 8-slot Wikimedia semaphore bounds throughput to roughly 10 images/s), 3 duplicates removed, 41 shown, 0 thumbnail failures, 11.3 s total; Nazarbayev University 94 candidates, 94 downloaded, 29 shown + 15 hidden, 8.7 s.
